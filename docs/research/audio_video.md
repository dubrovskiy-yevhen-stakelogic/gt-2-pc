# GT2 (PS1): аудио и видео — форматы, извлечение, нативное воспроизведение

Уровни уверенности: **[ВЫСОКАЯ]** — проверено мной на образах дисков или в первичном источнике; **[СРЕДНЯЯ]** — один источник сообщества / косвенные данные; **[НИЗКАЯ]** — гипотеза или только память.


---

## 0. TL;DR

1. Звук GT2 — это **четыре независимых подсистемы**, и для каждой нужен свой путь в нативном порте:
   - **Стриминговая музыка** — `MUSIC.DAT` в корне диска: один CD-XA файл, XA-ADPCM stereo 37800 Гц 4-bit, 22 номера каналов, упакованы в 4 параллельных "слота" (1x скорость). **[ВЫСОКАЯ, проверено на образах]**
   - **Секвенсорная музыка меню** — `sound/*.seq` (magic `SEQG`, 10 файлов) + банки инструментов `*.ins` (magic `INST`, 5 файлов) внутри `GT2.VOL`. Это **собственный формат Polyphony, а не Sony SEQ/VAB**. **[ВЫСОКАЯ]**
   - **Звуки двигателя/выхлопа** — файлы `.es` (magic `ENGN`), **2747 штук** в `GT2.VOL` Simulation-диска, несжатые, выровнены по секторам. Контейнер из нескольких SPU-ADPCM (VAG-подобных) лупов с параметрами "RPM fade-in / RPM pitch / RPM fade-out / volume / sample rate". **[ВЫСОКАЯ по структуре, СРЕДНЯЯ по точной семантике микширования]**
   - **SFX** (удары, визг шин, blow-off, UI) — те же `INST`-банки (`se01.ins`, `sys.ins`, `arcade.ins`). **[СРЕДНЯЯ]**
2. **Видео (FMV)** есть только на Arcade-диске: `STREAM.DAT`, 27 роликов. Это **не стандартный STR**: сектор с magic `0x53490160`, кадры в битстриме типа **"iki"** (per-block qscale + LZSS), MDEC-совместимые коэффициенты. Поддерживается jPSXdec (отдельный модуль `granturismo`). На Simulation-диске FMV-секторов нет вообще. **[ВЫСОКАЯ, проверено]**
3. Готовых permissive-библиотек "SPU целиком" практически нет: точные реализации SPU — GPL (Mednafen, PsyDoom, Avocado, PCSX-Redux, SwanStation) или CC-BY-NC-ND (современный DuckStation). Но нам **не нужна эмуляция SPU** — нужен "SPU-подобный" микшер голосов (ADPCM-декод + pitch + ADSR + опциональный reverb), это ~800–1500 строк C++ по открытой документации psx-spx. Рекомендация: **писать свой**, GPL-реализации использовать только как эталон для сравнения звука.
4. Рекомендуемый стек: **miniaudio** (public domain / MIT-0) или **SDL3 audio** (zlib) как устройство вывода; свой микшер 44.1 кГц; свой XA-декодер (~100 строк); свой секвенсор SEQG; для VR-пространственного звука — **Steam Audio** (Apache-2.0). FMV: сначала офлайн-конвертация через jPSXdec, позже — собственный декодер iki/MDEC по MIT-документу `PlayStation1_STR_format.txt`.

### 1.3 Japan Disc 1 (Arcade, SCPS-10116)

Корень: `GT2.OVL`, `GT2.VOL` (207 036 416), `MUSIC.DAT` (**96 059 392** — больше, чем в US-версии: 85 262 336), `SCPS_101.16`, `STREAM.DAT` (327 127 040), `SYSTEM.CNF`. Разный размер `MUSIC.DAT` подтверждает региональные различия в лицензированной музыке. **[ВЫСОКАЯ]**

### 1.4 Раскладка MUSIC.DAT (US)

Весь файл — XA-ADPCM, **один file number (1), номера каналов 0..21**. Это не классический 8/16/32-канальный interleave: одновременно чередуются только **4 канала** (каждый 4-й сектор принадлежит одному треку → ровно то, что нужно для stereo/37.8 кГц на **1x** скорости привода), а когда трек заканчивается, его "слот" занимает следующий трек ("тетрис-упаковка"). Последовательность наборов каналов по ходу файла:

`{1,3,5,6}` → `{1,2,3,6}` → `{2,3,4,6}` → `{2,4,6,8}` → `{2,4,8,9}` → `{2,4,9,21}` → `{4,9,19,21}` → `{4,10,19,21}` → `{7,10,19,21}` → `{7,10,18,21}` → `{7,10,18,20}` → `{7,12,18,20}` → `{12,14,18,20}` → `{11,13,18,20}` → `{13,15,18,20}` → `{15,17,18,20}` → `{0,16,18,20}` → `{0,16}`.

Число секторов по каналам (≈ длительность: 1 сектор stereo = 2016 сэмплов ≈ 53.3 мс): ch6 — 6297 (~5:36), ch3 — 5065, ch1 — 4893, ch5 — 4101, ch2 — 4082, ch4 — 3960, ch8 — 2951, ch9 — 2397, ch21 — 1685, ch19 — 1216, ch10 — 1186, ch7 — 1047, ch18 — 965, ch20 — 657, остальные (0, 11–17) — 60–217 секторов (джинглы по 3–12 с).

Это согласуется со сниппетом TCRF: в EXE лежат названия стриминговых треков — первые 6 зависят от региона (лицензированные песни), ещё 15 — меню/пред- и послегоночная музыка, стартовые/финишные джинглы Исаму Охиры (`ohira_01..18`), плюс 2 неиспользуемых коротких джингла ([tcrf.net/Gran_Turismo_2](https://tcrf.net/Gran_Turismo_2), только по сниппету поиска). **[СРЕДНЯЯ]** Следствие для порта: **номер канала = ID трека**, а стартовые сектора треков почти наверняка зашиты таблицей в EXE — её надо найти при реверсе (или просто вычислить сканированием субзаголовков, как сделал я).

OpenGTPS1 в своём `PORT_PLAN.md` отдельно отмечает, что XA читается на single-speed `ReadS` и что темп подачи секторов надо считать по точному NTSC-отношению `75 / (60000/1001)` секторов на VBlank, иначе музыка со временем заикается ([OpenGTPS1/docs/PORT_PLAN.md](https://github.com/GTTeancum/OpenGTPS1/blob/main/docs/PORT_PLAN.md)). Для нативного порта это нерелевантно (мы декодируем трек сами, без эмуляции привода), но подтверждает 1x-чтение. **[ВЫСОКАЯ]**

### 1.5 Раскладка STREAM.DAT (US Arcade) — 27 видеопотоков

Заголовок data-сектора (32 байта) совпадает с описанием в jPSXdec `SectorGTVideo`: magic `0x53490160`, chunk #, chunks in frame, frame #, used demux size, **total frames** (u16 @16), флаги первого/последнего чанка (u16 @18: 0x8000/0x4000/0xC000), 12 нулевых байт ([SectorGTVideo.java](https://github.com/m35/jpsxdec/tree/readme/jpsxdec/src/jpsxdec/modules/granturismo)). Размеров кадра в заголовке сектора нет — они берутся из заголовка iki-битстрима кадра (u16 codes, `0x3800`, width, height). Мой проход по заголовкам:

| # | Кол-во | Разрешение | Кадров | FPS (при 150 сект/с) | Длительность | Вероятное назначение |
|---|---|---|---|---|---|---|
| 1–24 | 24 | **112×96** | 419 | ~29.97 | ~14.1 с | маленькие превью (трассы/режимы в Arcade-меню) — гипотеза |
| 25 | 1 | **320×192** | 4649 | 29.97 | ~155 с | вступительный ролик — гипотеза |
| 26 | 1 | **640×216** | 3934 | ~15 | ~263 с | hi-res ролик (титры/концовка?) — гипотеза |
| 27 | 1 | **640×224** | 4999 | ~15 | ~334 с | hi-res ролик — гипотеза |

Аудио во всех роликах: XA stereo 37800 Гц, каждый 8-й сектор (2x скорость). Структура/счётчики — **[ВЫСОКАЯ]**, назначение роликов — **[НИЗКАЯ]** (проверить просмотром через jPSXdec).

### 1.6 Звуковые файлы внутри GT2.VOL (Sim-диск)

Сканирование начала каждого сектора `GT2.VOL` на magic:

- `ENGN` — **2747** вхождений, файлы несжатые, выровнены по 2048. Пример заголовка первого: `+0x08=0x50` (размер области заголовка), `+0x10=0xFA0` (размер данных сэмплов), `+0x14=0x50`, `+0x18=2` (число сэмплов), `+0x1C=0x30` (смещение таблицы параметров).
- `INST` — **5** вхождений (= `arcade.ins`, `arcseq.ins`, `gtmseq.ins`, `se01.ins`, `sys.ins`). Первые 0x20 байт заголовка устроены так же, как у `ENGN` (magic, 0, header size, 0, data size, header size, count, offset=0x28) — т.е. ENGN и INST — одно семейство контейнеров. Пример: count=0x16/0x2A/0xE2.
- `SEQG` — **10** вхождений (= `arcade.seq` + `spu_02..spu_10.seq`). Заголовок: magic, 0, seqCount=1, `0x4000`, значение темпа (например `0x1A286C` → 240000000/1714284 ≈ 140 BPM по формуле из gtseq2midi), далее 16 указателей треков начиная с `0x54`.
- `VAGp`, `pBAV` (VAB), `pQES` (Sony SEQ) на границах секторов **не найдены** → стандартные форматы Sony libsnd (VAB/VH/VB/SEQ) GT2, судя по всему, **не использует**; у Polyphony собственный звуковой драйвер. **[ВЫСОКАЯ для "на границах секторов"; внутри gzip-сжатых файлов VOL я не искал]**

## 2. Форматы: что известно сообществу

### 2.1 ENGN / `.es` — звук двигателя

Источники: тред GTPlanet "Gran Turismo 2 Sound Modding" ([стр.1](https://www.gtplanet.net/forum/threads/gran-turismo-2-sound-modding.353348/), [стр.2](https://www.gtplanet.net/forum/threads/gran-turismo-2-sound-modding.353348/page-2)), документ Submaniac "Gran Turismo 2 – In-depth file info" ([PDF на GT Modding Hub](https://nenkai.github.io/gt-modding-hub/ps1/gt2/documents/Gran_Turismo_2_files_full_documentation.pdf)), [TheAdmiester/GranTurismoENGNEditor](https://github.com/TheAdmiester/GranTurismoENGNEditor).

- Формат один и тот же в GT1–GT3 (по словам Xenn; редактор TheAdmiester заявляет GT1–GT4). Little-endian. **[СРЕДНЯЯ]**
- Заголовок (сводка Xenn + Submaniac, совпала с тем, что я вижу на диске): `0x00 "ENGN"`, `0x08` размер заголовочной области, `0x10` размер файла минус заголовок, `0x14` размер заголовка (дубль), `0x18` число сэмплов, `0x1C` смещение таблицы параметров. Далее по **16 байт на сэмпл**: `+0 u16` RPM начала fade-in, `+2 u16` "RPM pitch" (обороты, на которых записан луп = центр высоты тона), `+4 u16` RPM fade-out, `+6 u16` громкость (до 32767), `+8 u32` sample rate / 10 (22050 Гц → 2205), `+0xC u32` смещение сэмпла. **[ВЫСОКАЯ по раскладке, СРЕДНЯЯ по семантике первых трёх полей — у Xenn и Submaniac порядок fade-in/pitch описан чуть по-разному]**
- Данные — SPU-ADPCM (16-байтные блоки по 28 сэмплов, loop-флаги в блоках), PSound читает их как набор VAG. README редактора называет кодек "HEVAG", но для PS1 это обычный PS-ADPCM (HEVAG — более позднее расширение); важно лишь, что длина кратна 28 сэмплам. **[СРЕДНЯЯ]**
- Рекомендации моддеров по значениям: громкость 24000–32000 для выхлопа, 16000–24000 для "engine"; fade-in обычно = RPM pitch предыдущего слоя, у последнего слоя fade-out = 32767, чтобы звук не затухал выше последнего лупа. Наблюдение Submaniac: сэмплы хранятся сильно "замедленными" (для 787B нужно ускорение ~2.5x, чтобы совпасть с 8000 rpm) — т.е. игра активно питчит вверх. **[СРЕДНЯЯ]**
- Набор файлов на машину (Submaniac): `xxxxx.es` — "engine"/впуск (не меняется от тюнинга); `xxxxx_n0..n3.es` — выхлоп для атмосферников по стадиям глушителя (stock/sport/semi-race/race); `xxxxx_t0..t3.es` — то же для турбо. Установка турбо на NA-машину переключает игру на t-набор. Лимит — до 3399 `.es`. ID звукового файла двигателя задаётся полем `SoundFile` в таблице Engine базы параметров (пример значения: 21204). **[СРЕДНЯЯ]**
- Вывод для порта: на машину одновременно играют как минимум **2 банка** (engine + exhaust), в каждом несколько лупов, кроссфейд по RPM + питч пропорционально `rpm / rpm_pitch`. Точные кривые громкости (линейная? зависимость от газа/нагрузки? поведение турбо/blow-off, доплер для соперников) сообществом **не описаны** — это предмет реверса EXE и сверки по трассировке SPU (см. §6).

### 2.2 SEQG / `.seq` — секвенсорная музыка

- [xan1242/gtseq2midi](https://github.com/xan1242/gtseq2midi) (C++, MIT, 27 коммитов) конвертирует SEQG в MIDI; подтверждена работа с GT2 и GT3, GT1 "с багами". Формальной документации формата в репозитории нет ("coming soon"), но по коду: главный заголовок (magic, неизвестный указатель, число секвенций), на секвенцию — master volume, темп (BPM = 240000000 / значение), 16 указателей треков; события — VLV-дельты как в MIDI, без running status; ноты `0x80–0xEC` с velocity и VLV-длительностью (т.е. note-off не отдельным событием), команды volume/pan/instrument, pitch bend, loop marker, end of track. **[СРЕДНЯЯ — по чтению кода чужим инструментом суммаризации]**
- Состав в GT2 (Submaniac): `arcade.seq` (музыка меню Arcade) + `arcseq.ins`; `spu_02..spu_10.seq` (Car Wash, East/North/South/West City, GT-раздел, My Home, карта/главное меню, License) + общий банк `gtmseq.ins` (PSound видит в нём 107 сэмплов, в `arcseq.ins` — 40). Формат совпадает с GT1: западные GT1-треки можно подставить в GT2 вместе с `.ins`; слишком большой `.ins` (JP GT1) роняет игру — память под банк выделена жёстко. **[СРЕДНЯЯ]**
- По данным форума HCS: секвенсорные треки EU/US-версий писал Jason Page, японские — Isamu Ohira; XA-треки тоже региональные ([hcs64 thread](https://hcs64.com/mboard/forum.php?showthread=62736) — речь там о GT1, переносимость на GT2 — **[НИЗКАЯ]**).

### 2.3 INST / `.ins` — банки инструментов и SFX

- Публичного описания PS1-варианта INST **я не нашёл**. Есть описание GT4-варианта: [Nenkai/GT4SoundTool](https://github.com/Nenkai/GT4SoundTool) (C#, MIT, помечен UNFINISHED): иерархия `InsHeader → EsHeader → JamHeader → JamProgramChunk → JamSplitChunk` (диапазоны нот, ADSR, volume, pan, индекс LFO), сэмплы — VAG с loop-данными; ADSR и LFO там не разобраны. Насколько это совпадает с GT2 — неизвестно, но общие первые 0x20 байт с ENGN и слово "Es" в названии структуры намекают на родство. **[НИЗКАЯ–СРЕДНЯЯ]**
- [JeevesGB/GTExplorer](https://github.com/JeevesGB/GTExplorer) (Python/PyQt6, MIT, 144 коммита, для GT1) заявляет "INST/ENGN sample expansion" и распознаёт `INST/ENGN/SEQG`; в `doc/formats.md` детальной раскладки нет — смотреть исходники. **[СРЕДНЯЯ]**
- Содержимое SFX-банков по Submaniac: `se01.ins` — гоночные SFX (15 сэмплов: стартовый сигнал 3-2-1, удары, скольжение, backfire — часть неиспользуемые), `sys.ins` — UI-звуки меню (8), `arcade.ins` — набор SFX (19: удары, большой краш, blow-off, задний ход и т.д.), возможно наследие GT1. **[СРЕДНЯЯ]**
- Вывод: INST придётся реверсить самим (сам контейнер простой; сложность — в полях ADSR/питча/корневой ноты и в том, как драйвер их применяет). Быстрый путь — трассировка записей в регистры SPU в эмуляторе (§6).

### 2.4 XA-ADPCM (MUSIC.DAT, звук роликов)

Стандарт CD-XA, документирован в psx-spx ([XA ADPCM](https://problemkaputt.de/psxspx-cdrom-xa-audio-adpcm-compression.htm)): в секторе 18 звуковых групп по 128 байт (16 байт заголовков + 112 байт данных), 8 sound units × 28 сэмплов (4-bit); в байте заголовка shift (0–12) и номер фильтра (4 фильтра: коэффициенты 0/60/115/98 и 0/0/−52/−55, деление на 64). Железо ресемплит 37800→44100 (7:6) "zigzag"-интерполяцией — для порта точное повторение не обязательно, достаточно качественного ресемплера. **[ВЫСОКАЯ]**

### 2.5 SPU-ADPCM / VAG / VAB

- PS-ADPCM: блок 16 байт = байт shift/filter (5 фильтров) + байт флагов (loop start / loop end / repeat) + 28 нибблов; 24 голоса, pitch `0x1000` = 44100 Гц, максимум `0x4000`; 4-точечная "гауссова" интерполяция по таблице 512 значений; ADSR с экспоненциальными/линейными режимами; реверб считается на 22050 Гц, 10 стандартных пресетов (Room, Studio S/M/L, Hall, Half/Space/Chaos Echo, Delay, Off) — всё расписано в [psx-spx SPU](https://psx-spx.consoledev.net/soundprocessingunitspu/). **[ВЫСОКАЯ]**
- Стандартные VAB/VH/VB/SEQ (libsnd) в GT2, судя по отсутствию magic, не используются (§1.6) — тратить время на VAB-парсеры не нужно. Использует ли GT2 аппаратный реверб (туннели?) — **неизвестно**, проверять трассировкой SPUCNT/регистров реверба.

### 2.6 Видео: GT-вариант STR + битстрим "iki"

- Контейнер: §1.5. Кадр: битстрим семейства **iki** — в отличие от обычных BS v2/v3 у каждого блока свой quantization scale, а qscale/DC сжаты LZSS; AC-коэффициенты — обычные MDEC VLC. Формат описан в `PlayStation1_STR_format.txt` из jPSXdec, и **сам этот документ под MIT** ([файл](https://github.com/m35/jpsxdec/blob/readme/jpsxdec/PlayStation1_STR_format.txt); раздел про Gran Turismo — 3.13, про iki — 3.10; в документе сказано, что GT1 и GT2 хранят видео одинаково и главная особенность — отсутствие размеров в заголовке сектора). **[ВЫСОКАЯ по наличию и лицензии документа; детали iki я прочитал лишь частично — инструмент обрезал файл]**
- ffmpeg: демультиплексор `psxstr` опознаёт видео-секторы по биту video в submode и стандартному заголовку; у GT-секторов submode = data (0x48) и другой magic → **вероятно, ffmpeg STREAM.DAT от GT2 не разберёт** (не проверял запуском). Декодер `mdec` в ffmpeg рассчитан на BS v2/v3. Лицензия LGPL 2.1+ ([psxstr.c](https://www.ffmpeg.org/doxygen/4.0/psxstr_8c_source.html)). **[СРЕДНЯЯ]**

## 5. Рекомендуемая нативная аудио-архитектура

```
                +------------------ game thread ------------------+
                |  CarAudio (ENGN model)   SfxBank (INST)         |
                |  MusicSeq (SEQG player)  XaStream (MUSIC.DAT)   |
                +------------------------+------------------------+
                                         | lock-free команды (key on/off, pitch, vol, pan, 3D pos)
                +------------------------v------------------------+
                |  gt2mix: N голосов (не 24, а 64–128)            |
                |   - PCM int16 (PS-ADPCM декодируется при загрузке) |
                |   - pitch 4.12/16.16 fixed, loop start/end      |
                |   - интерполяция: gauss(PS1) | cubic/sinc (HQ)  |
                |   - ADSR в семантике SPU                        |
                |   - send -> Reverb (PS1-модель 22.05k | modern) |
                |   - шины: engine / sfx / music / ui / fmv       |
                |  Spatializer (VR): Steam Audio HRTF на шине 3D  |
                +------------------------+------------------------+
                                         | float32 stereo 48k
                          miniaudio / SDL3 audio device callback
```

Ключевые решения:

1. **Устройство вывода:** [miniaudio](https://github.com/mackron/miniaudio) (public domain / MIT-0, single-file, WASAPI на Windows, AAudio/OpenSL на Android → годится для будущего Quest standalone, есть ресемплер и node graph) **или** аудио-подсистема [SDL3](https://github.com/libsdl-org/SDL) (zlib), если SDL3 и так берётся для окна/ввода. Оба варианта permissive. OpenAL Soft (LGPL) не нужен.
2. **Внутренняя частота микшера — 44100 Гц** (родная для SPU: питч `0x1000` = 44.1k, реверб на 22.05k), на выходе ресемплинг в частоту устройства (48k у большинства VR-гарнитур). Так числа из игровых данных (pitch-регистры, ADSR-скорости) переносятся 1:1.
3. **PS-ADPCM декодировать заранее** в int16 при загрузке банка (2747 `.es` маленькие: пример — 4 КБ данных на файл), хранить loop-точки из флагов блоков. Это упрощает интерполяцию и HQ-режим. Нюанс: у SPU состояние предиктора на границе лупа не сбрасывается — при предекоде лупа декодировать "второй проход" отдельно или принять микроскопическую разницу.
4. **Режимы "Authentic / Enhanced":** гауссова интерполяция + PS1-реверб против cubic/sinc + современного реверба. Дёшево, а для аудитории ремастера важно.
5. **Двигатель (`CarAudio`)**: на каждую машину 2 ENGN-банка (engine + exhaust по стадии глушителя и NA/turbo). Для слоя `i`: `pitch_ratio = rpm / rpm_pitch[i]`, шаг голоса = `pitch_ratio * (rate10[i]*10 / 44100)`; громкость — кроссфейд по `fade_in..rpm_pitch..fade_out` × `volume/32767` × (газ/нагрузка — **уточнить реверсом**). Это гипотеза из семантики полей; обязателен этап сверки с оригиналом (§6). Для машин соперников — те же банки + дистанционное затухание/доплер (в оригинале, вероятно, упрощённо; в VR делаем честное 3D).
6. **SFX (`SfxBank`)**: INST-банки → голоса с ADSR из банка; визг шин/ветер, вероятно, модулируются питчем/громкостью от скольжения/скорости — параметры искать в EXE.
7. **Секвенсор (`MusicSeq`)**: свой проигрыватель SEQG (16 треков, VLV, ноты с длительностью, program/volume/pan/pitch-bend, loop marker) поверх того же микшера и `gtmseq.ins`/`arcseq.ins`. gtseq2midi (MIT) — справочник по событиям. Альтернатива "конвертировать в MIDI + SoundFont" хуже: теряется аутентичность и всё равно нужен INST.
8. **XA-музыка (`XaStream`)**: собственный декодер XA (~100 строк; сверка с vgmstream ISC). Два режима: (а) читать прямо из `.bin` образа пользователя по таблице "канал → список секторов" (индекс строится один раз сканированием субзаголовков — как в моей утилите); (б) офлайн-демультиплекс в `work/music/track_XX.(xa|flac)`. Плюс **поддержка пользовательских замен** (OGG/FLAC по имени трека), как сделано в OpenGTPS1 — полезно из-за региональных саундтреков и лицензий: сами треки распространять нельзя, только читать с диска пользователя.
9. **FMV**: этап 1 — офлайн через jPSXdec в `work/fmv/` и проигрывание современным кодеком (например, MPEG-1 через [pl_mpeg](https://github.com/phoboslab/pl_mpeg), MIT, single-header — самый дешёвый вариант встраивания); этап 2 — собственный декодер GT-STR + iki + IDCT/YCbCr→RGB на C++ по MIT-документу jPSXdec (оценка 600–1000 строк), чтобы игра работала напрямую с образа без конвертации. В VR ролики показывать на виртуальном экране. Маленькие 112×96 превью, возможно, разумнее заменить рендером в реальном времени — решать после идентификации роликов.
10. **VR-звук**: [Steam Audio](https://github.com/ValveSoftware/steam-audio) 4.8.1, Apache-2.0, C API, Windows + Android (arm64) — HRTF для машин соперников, отражения/окклюзия опционально. Собственный двигатель игрока в кокпите — без HRTF (или слабая пространственность: выхлоп сзади, впуск спереди — бесплатный "вау"-эффект для VR). miniaudio имеет и встроенный простой spatializer как fallback.

## 6. Как получить "ground truth" звукового движка (план реверса)

Параметры микширования двигателя и применение INST сообществом не задокументированы. Самый быстрый путь — не дизассемблер, а **трассировка SPU** в имеющемся форке эмулятора (у пользователя уже есть опыт GP0-захвата в fighting-force-vr — здесь то же самое для звука):

1. В SwanStation/своём DuckStation-форке логировать записи в регистры голосов (`0x1F801C00..0x1F801D7F`: vol L/R, pitch, start addr, ADSR, repeat addr), KON/KOFF, SPUCNT, регистры реверба, а также DMA-загрузки в SPU RAM (адрес+длина+хеш → сопоставление с сэмплами из ENGN/INST).
2. Одновременно логировать игровые переменные (RPM, газ, скорость, скольжение) — адреса находятся поиском по RAM или из реверса.
3. По логам строятся: кривая `pitch(rpm)` для каждого слоя, кривые громкости/кроссфейда, распределение 24 голосов (сколько на игрока, сколько на соперников, сколько на SFX), использование реверба, поведение при переключении передач/отсечке/турбо.
4. Те же логи = регрессионные тесты микшера порта (подать те же команды → сравнить спектр/RMS с записью эмулятора).

Параллельно при декомпиляции EXE искать: таблицу треков XA (номер канала, стартовый LBA относительно `MUSIC.DAT`, длина), таблицу роликов `STREAM.DAT`, парсеры `ENGN`/`INST`/`SEQG` (по magic-строкам), тик секвенсора (скорее всего от VBlank или таймера RCnt).

## 7. Риски и открытые вопросы

- Точная семантика полей ENGN (что именно fade-in/fade-out, есть ли зависимость от нагрузки/газа, как выбирается пара engine+exhaust, что такое "AI turbo / AI non-turbo" варианты из треда GTPlanet) — не закрыто.
- Формат INST для PS1 — публично не описан; GT4-описание лишь ориентир.
- Использует ли GT2 реверб SPU, pitch modulation, noise-канал — неизвестно.
- Назначение 27 роликов `STREAM.DAT` и отличия JP/PAL-версий (набор роликов, треков) — проверить просмотром; PAL-образа у пользователя нет.
- jPSXdec — non-commercial лицензия: использовать только как внешний инструмент, не линковать и не копировать код; спецификация формата (MIT) — можно.
- Лицензированная музыка (первые 6 XA-треков, зависят от региона) и ролики — распространять нельзя; порт должен читать их с дисков пользователя. Bonus-диск "Music at the Speed of Sound" (есть у пользователя) содержит CD-DA дорожки — потенциальный источник более качественных версий части треков для опциональной замены (**[НИЗКАЯ]**, состав не проверял).
- psxavenc архивирован (январь 2026) — как энкодер для модов всё ещё годится, но без поддержки.

## 8. Предлагаемые первые шаги (аудио/видео-трек плана)

1. `tools/disc_index` (C# или C++): индекс образа → JSON в `work/` (файлы, LBA, карта XA-каналов `MUSIC.DAT`, список роликов `STREAM.DAT`). Прототип логики уже проверен в этом исследовании.
2. `tools/xa_dump`: XA → WAV по каналу (валидация декодера против вывода jPSXdec).
3. `tools/engn_dump`: ENGN → JSON параметров + WAV лупов; массовая статистика по 2747 файлам (распределение числа слоёв, rpm_pitch, rate) — сразу прояснит семантику полей.
4. `tools/inst_dump`, `tools/seqg_dump`: разбор заголовков, выгрузка сэмплов; SEQG → MIDI для сверки с gtseq2midi.
5. SPU-трассировщик в форке эмулятора (§6).
6. `gt2mix` + `CarAudio` прототип: standalone-приложение "ползунок RPM → звук двигателя выбранной машины" — дешёвая и очень наглядная ранняя веха.
7. FMV: офлайн-конвертация jPSXdec → идентификация роликов → решение по собственному iki-декодеру.
