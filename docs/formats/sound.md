# Звук гонки в GT2 (US Simulation v1.2, EXE SHA-1 3030aa271c0a4022fc69ce09d76a6bc75e69a32a)

Дата: 2026-09-19. Источники: наш дизассемблер/декомпиляция трассы загрузки гонки (`work\re\race_load`: `functions.txt`,
`edges.txt`, `decomp\<ADDR>.c`, `ram.bin`), байты файлов `work\disc_sim_us12\vol\engine\*.es`, `vol\sound\se01.ins`,
таблица GTDT `carparam\usa_gtmode_data.dat`. Адреса - Sim v1.2, RAM-дамп `work\re\race_load\ram.bin` (гонка-заставка).
Реализация: `src\gt2formats\sound_bank.*` (парсер), `src\game\audio\*` (перенос логики, микшер, вывод),

## 1. Контейнеры ENGN (`engine/*.es`) и INST (`sound/*.ins`)

Общий заголовок (LE):

| Смещение | Значение | Улика |
|---|---|---|
| +0x00 | magic `ENGN` (0x4E474E45) / `INST` (0x54534E49) | `0x80079078` / `0x80078974` сравнивают `*param_1` |
| +0x04 | self-указатель (0 на диске; после загрузки = адрес заголовка в RAM) | `param_1[1] = param_1` там же; в дампе 0x8017DDD0 -> 0x8017DDD0 |
| +0x08 | размер заголовка (0x50/0x80/0xB0 у .es; 0x1B4 у se01.ins) | байты файлов |
| +0x0C | адрес данных в SPU RAM (0 на диске; загрузчик записывает свой) | `param_1[3] = param_2` (SPU-адрес); в дампе 0x1CC70 для 20403.es |
| +0x10 | размер данных (SPU-ADPCM), грузится в SPU RAM сразу после заголовка | `0x800680A0`: `param_1[7] = *(file+0x10)`, DMA `0x8007C268` |
| +0x14 | размер заголовка (дубль; релоцируется как указатель) | `0x800680A0`: `*(file+0x14)` = байты, читаемые в RAM |
| +0x18 | число записей таблицы 0 | `0x80078F10` берёт `bank+0x18` как число слоёв |
| +0x1C | смещение таблицы 0 (0x30 у .es, 0x28 у .ins) | `0x80078F10`: `bank+0x1C` -> указатель таблицы |
| +0x20 / +0x24 | число / смещение таблицы 1 (ENGN: второй набор слоёв, на диске 0; INST: список "программ") | `0x80079078` релоцирует оба набора (шаг 8 байт) |

Файлы сектор-выровнены и не сжаты (2747 `.es` = 305 наборов x 9 файлов + `ene_n.es`, `ene_t.es`).

### 1.1 Слой ENGN (16 байт, `gt2::EngineLayer`)

| +0 | s16 rpmPitch | обороты, при которых луп играет с высотой `pitch` (делитель в `0x80078A54`) |
| +2 | s16 fadeIn | слой звучит один при fadeIn <= rpm <= fadeOut (`0x80078C88`) |
| +4 | s16 fadeOut | |
| +6 | s16 volume | 0x4000 = 1.0 (`0x80078B00`) |
| +8 | u32 pitch | регистр pitch SPU при rpmPitch (0x1000 = 44100 Гц) |
| +C | u32 sampleAddress | смещение лупа в области данных; после загрузки `+= SPU-адрес данных` (`0x80079078`); в голос уходит `>> 3` |

Пример `engine/20403.es` (Shelby GT350 '66 из заставки, банк в RAM 0x8017DDD0, таблица 0x8017DE00): слои
(1000,0,1000,0x13A7,0x744,0), (2000,2000,2000,0x1A34,0x802,0x2610), (3000,3000,3000,0x1FBF,0x71C,0x44C0),
(4000,4000,4000,0x2E5C,0x7A3,0x5CF0), (5000,5000,32767,0x3264,0x744,0x7240); в RAM +C = 0x1CC70, 0x1F280, ... -
смещение + SPU-адрес. Данные - обычный PS1 SPU-ADPCM (блоки 16 байт, флаги loop start/end/repeat в байте 1).

### 1.2 Сэмпл INST (20 байт, `gt2::InstSample`)

| +0 | u16 address | смещение данных / 8 (после загрузки += SPU-адрес / 8, `0x80078974`) |
| +2 | s16 volume | масштаб громкости one-shot (`0x800784A0`: `vol * volume >> 14`) |
| +4 | u16 baseNote | нота записи << 8 \| fine (`0x8007A52C`) |
| +6 | u16 duration | длительность в единицах драйвера (0 = до Release) |
| +8 | u8 priority | приоритет голоса по умолчанию |
| +A | u8 flags | бит 0 = реверб (в голос как есть) |
| +C | u8 note | воспроизводимая нота |
| +10 | u16 adsr1, +12 u16 adsr2 | регистры ADSR SPU |

`sound/se01.ins`: 18 сэмплов, таблица 1 - две "программы" (`{count, 0x40, 0, 0x40, список индексов}`) - гонкой не используются.
Индексы, которые использует гонка, лежат в оверлее: `0x8002F528` = {0x11 турбо-свист, 0x0B визг шин (покрытие 0),
0x0F покрытие 1, 0x0E покрытие 5, 0x0A blow-off, 0x05 удар о стену}; `0x8002F530` = {0,1,2,3} - пары "левый/правый"
сигналов старта (`0x800189C4`: пара [2p], [2p+1]; при разных индексах первый на pan 0, второй на pan 0x7F).

## 2. Какой банк у какой машины

- Номер набора звука двигателя = `EngineRow::word0A` таблицы 6 GTDT (`car_params.h`), который строитель копирует в
  `CarConfig::engineWord` (+0x76). В дампе запись игрока 0x801D5934: +2 = 0x4FB3 = 20403 -> `engine/20403.es`.
  Загрузчик `0x8001882C`: `fn_80060DE0(id)` - бинарный поиск id в отсортированной таблице 0x801DF340 (305 = 0x131 записей,
  `DAT_801C93BC`) -> порядковый номер набора; индекс файла в VOL = `DAT_801E306E` (первый `.es`) + номер * 9.
- Выхлоп: файл `+1 + exhaustByte` внутри девятки `xxxxx.es, _n0.._n3, _t0.._t3` (`CarConfig::exhaustByte` +0x78: ступень
  глушителя, +4 при турбо-ките) -> `engine/%05u_n%u.es` / `_t%u.es`.
- Игрок (car+0x18 = класс управления 2..3): `0x800145F4` -> `0x80018138(mode 0)`: банк "engine" в объект +0x24, банк
  выхлопа в +0x4C. Машины ИИ (car+0x18 < 2): mode 1, только выхлоп из общего банка `engine/ene_n.es` (car+0x10 = 0)
  или `engine/ene_t.es` (турбо) - слоты 2/3 таблицы банков 0x8017DDA0 (по 0xC байт: {заголовок, размер, SPU-адрес}).
- Банк эффектов гонки `sound/se01.ins` -> `PTR_DAT_8017D894`.

## 3. Драйвер голосов (EXE, `0x80079DBC` init, `0x8007916C` тик 60 Гц)

Таблица 24 голосов по 0x28 байт с 0x801EFE68 (+0 состояние 0 свободен/1 занят/2 недоступен, +1 играет, +2 key-on
выполнен, +3 приоритет, +4 блокировка, +5 маска dirty (1 pitch, 2 громкость, 4 адрес+ADSR), +6 запрос key-on, +7
запрос key-off, +8/+A volL/volR, +C pitch, +E адрес/8, +10/+12 ADSR, +14 указатель на handle владельца, +18 счётчик
тиков, +1C duration*0x100, +20 сумма pitch по тикам, +24 реверб). Тик пишет регистры 0x1F801C00+v*0x10 и KON/KOFF;
голос с duration != 0 отпускается, когда сумма pitch превысит duration*0x100; по концу огибающей handle владельца
получает 0xFF. API (первый аргумент - указатель на int8 handle):
`0x8007A59C Play(handle, desc16)` (desc: +0 volL, +2 volR, +4 pitch, +6 адрес/8, +8/+A ADSR, +C duration, +E
приоритет, +F флаги; выбор голоса `0x8007A938`: свободный, иначе отбирает у равного/низшего приоритета),
`0x8007A614 SetPriority`, `0x8007A668 SetPitch`, `0x8007A6C8 SetVolume(u32 L|R)`, `0x8007A728 Release`, `0x8007A778 Detach`.
Таблицы EXE: высота ноты `0x8008FDB8` (384 x u16, 0x4000..0x7FC5 = 2^(i/384) октавы, `0x8007A52C`: шаг 0xC00 =
октава, результат сдвигается на октаву), панорама `0x800901B8` (128 x u16, 0..0x4000; L = vol*tab[0x7F-pan]>>14,
R = vol*tab[pan]>>14, `0x8007A170`). Общая громкость эффектов `0x801C9994` (u8, 0xC0 в дампе).

## 4. Объект звука машины (car + 0xAA4, 0x98 байт, `gt2::audio::CarSound`) и покадровая логика

Каждый кадр гонки (30 Гц) `0x80015B64` -> `0x80014E6C` обходит список машин, отсортированный по расстоянию до
камеры (`0x800140A4` строит список и пишет car+0x808 = громкость по расстоянию, car+0x80C = вектор машина-камера,
16.16 м), и вызывает `0x800146D8(car, ранг, камера)`:

- car+0x808: d = max|xyz| + mid/2 + min/4; vol = (0x80000, для ИИ вне заставки 0x18000) / ((d>>16)+1), не более
  0x4000, для ИИ < 0x400 -> 0.
- доплер (+2): при скорости камеры < c/2: `(c + vCam * dir.camDir >> 12) * 0x1000 / (c + vCar * dir.carDir >> 12)`,
  c = `0x800AF22C` = 0x5AAAA (`0x8001584C`: (340 << 16) * шаг / 60), vCar = car+0x868 = приращение позиции за кадр (16.16).
- pan (+0x10) = dir . ось камеры +0xF4 (в `0x8001826C`: индекс = ((pan+0x1000)>>1)*0x7F>>12).
- +0x16 engineVolume = 0x2000 * body+0x757 >> 7; +0x18 exhaustVolume = 0x4000 * body+0x758 >> 7; +0x1A turbo =
  0x1333 * body+0x759 >> 7 (в виде из машины: 0x2199/0x2B33/0x2199 или 0x3000/0x1800/0x3000, master = 0x4000,
  без pan/доплера); +0x22 blow-off = body+0x744 << 2 при > 0; +6 turboPitch = body+0x746 << 12 / 0x1800.
- Колёса (wheel+0x14 покрытие, +0x1D уровень дыма, +0x1F уровень пыли): покрытие 0 -> визг: sum(smoke)*0x10*k>>12
  (k = 0x1000; 0x3000 в заставке и для машины игрока), покрытие 1: sum*0x40, pitch = mean(dust)<<7; покрытие 5:
  sum*0x10, pitch = mean(dust)<<7 * 0x266 >> 12; всё <= 0x4000 / 0x3FFF.
- Удар о стену: для машины камеры, вне заставки, когда body+0x73E == частота кадров (таймер только что взведён
  `physics_core.cpp`), one-shot сэмпла [5] с громкостью min(0x1000, body+0x740 << 3) * 4 на pan 0x40.

`0x8001826C` (mix): L/R = master(0x801C9994) * PanVolume(masterVolume, pan) / 255 (<= 0x3FFF); громкости банков =
L/R * engineVolume(+0x16) / exhaustVolume(+0x18) >> 14 (mode 1: x0x333>>10); приоритеты = index*6 (+1 выхлоп, +2
турбо, +4 визг, +3 покрытия); голоса эффектов `0x800785A8` (pitch = NotePitch(note, baseNote) * (доплер [* turboPitch /
slipPitch >> 12]) >> 12; громкость 0/0 = Release+Detach); blow-off one-shot [4]; затем `0x80078C88` для engine (mode 0)
и exhaust (mode 0/1).

`0x80078C88` (плеер ENGN): rpm = max(200, obj+8); слой i с fadeIn <= rpm <= fadeOut -> слот0 = i, слот1 = -1; иначе
разрыв prev.fadeOut < rpm < i.fadeIn -> слот0 = i-1, слот1 = i (кроссфейд); слоты меняются местами, если так
сохраняется играющий голос. Слот с тем же слоем и живым голосом: `0x80078A54`/`0x80078B00` с ограничением изменения
(pitch в [prev/2, prev*2], громкость +-0x1000) и SetPitch/SetVolume; иначе Release+Detach старого и Play {vol, pitch,
адрес = layer+C >> 3, ADSR1 0x000F, ADSR2 0x0003, duration 0, приоритет obj+5, флаги 1 (реверб)}.

Формулы (целочисленные, MIPS):
- pitch (`0x80078A54`): `((u32)(layer.pitch * rpm) / (u32)layer.rpmPitch) * obj.pitchScale >> 12`, минимум 1.
- громкость (`0x80078B00`): доля t = 0x4000 внутри [fadeIn, fadeOut]; при rpm < fadeIn: t = (rpm - other.fadeOut) *
  0x4000 / (fadeIn - other.fadeOut); при rpm > fadeOut: t = (other.fadeIn - rpm) * 0x4000 / (other.fadeIn - fadeOut);
  g = (sin[(t >> 4) & 0xFFF] * 0x3FFF >> 12) * layer.volume >> 14 (sin - таблица 0x80093150, 4096 = 1.0);
  volL/R = obj.volL/R * g >> 14.

## 5. Что перенесено и как сверено

`src\game\audio\car_sound.cpp`: `DistanceVolume` (0x800140A4, часть), `DopplerFactor`, `NotePitch` (0x8007A52C),
`PanVolume` (0x8007A170), `PlaySample` (0x800784A0), `StartLightSound` (0x800189C4), `InitEngineSound` (0x80078F10),
`InitCarSound` (0x80018138), `EngineSlotPitch` (0x80078A54), `EngineSlotVolume` (0x80078B00), `UpdateEngineSound`

`MixCarSound` (0x8001826C), `UpdateCarSound` (0x800146D8, целочисленная часть; нормализация векторов и скалярные
произведения GTE-функций 0x80081164/0x80081500 заменены нативной векторной математикой).

Стенд `gt2verify` (строки EngPitch 0x80078A54, EngVolume 0x80078B00, EngUpdate 0x80078C88, CarMix 0x8001826C):
оригинал в интерпретаторе на дампе против порта, сравнение всей RAM; таблица драйвера переводится в состояние
"недоступен", чтобы оба работали только с объектом звука. Результат 2026-09-19 (`build_sound\gt2verify.exe
work\re\race_demo\ram.bin`): EngPitch 336 случаев, EngVolume 336, EngUpdate 672, CarMix 288 - 0 расхождений.
Оракул в рантайме: `gt2play --spu-log <файл>` пишет все записи регистров голосов и объект звука машины 0 по полям
(rpm, доплер, слоты/pitch/громкости). Пример из `work\play\spu_log.txt` (поле 2154, гонка-заставка, набор 20403):
rpm 6264, доплер 0x103C, слот 1 = слой 4 (rpmPitch 5000, pitch 0x744, volume 0x3264), громкость банка 630/593 ->
pitch = (1860*6264/5000) * 0x103C >> 12 = 0x93C (в логе 0x93C), громкость = 630 * ((4096*0x3FFF >> 12) * 0x3264 >> 14)
>> 14 = 495 (в логе 495).

Не перенесено: SEQG-секвенсор меню, вибрация. Скорость звука взята из дампа (0x5AAAA при `param+0x18` = 1 в
`0x8001584C`). Музыка и реверб - разделы 6 и 7 (2026-09-19).

## 6. Музыка гонки: XA-треки `MUSIC.DAT`

Источники: дизассемблер/декомпиляция `work\re\race_load` (0x800299D8, 0x80029B60, 0x80029C54/60/84, 0x80080F24,
0x8008103C, 0x80083AE0, скрипты CD-драйвера 0x800903E4..), RAM трёх дампов (`race_load`, `race_demo`, `license_race`),
байты `SCUS_944.88` и секторы `MUSIC.DAT` образа, лог команд CD-ROM рантайма (`gt2play --cd-log`, ниже).

**Файл.** `MUSIC.DAT` в корне ISO (LBA 238872 = 0x3A518, 41632 сектора): только XA-аудио сектора Mode 2 Form 2,
file 1, coding 0x01 (стерео, 37800 Гц, 4 бита), каналы 0..21, в каждый момент чередуются 4 канала (1 сектор канала
на 4 сектора диска = ровно поток 1x). База `0x80095AC0` (u32, заполняется при загрузке; в дампах 0x3A518 = LBA файла),
указатель на таблицу `0x80095ABC` (-> 0x800959C0).

**Таблица треков** `0x800959C0` (EXE, инициализированные данные; 21 запись по 12 байт): `{u32 указатель на имя, u32 first,
u32 end}`, секторы относительно начала `MUSIC.DAT`. Трек `id` = XA file 1, канал `id + 1` (`0x80080F24`: байт 0x801F0533 =
id + 1, 0x801F0532 = 1). Проверено стендом (строка `XaTable`, сканирование всех секторов файла): для каждого id первый
сектор канала id+1 = `first`, последний < `end`, у всех coding 0x01, file 1; канал 0 (152 сектора в конце) в таблице не
упоминается. Длительность `0x8008103C` = `(end - first + 74) / 75` секунд (секторы потока 1x).

**Байты задачи гонки** (объект `*(0x8002F4F4)`, в дампах 0x801FF8B8): +0x70 состояние ГСЧ задачи, +0x2EC текущий id у
драйвера, +0x2ED флаг цикла запроса, +0x2EE запрос (0xFF = тишина), +0x2EF трек гонки, +0x2F0 следующий после конца
нециклического, +0x2F1 вид джингла.

- `0x800299D8` (загрузка гонки, после выдержки 0x8001584C; порт `audio::InitRaceMusic`, строка стенда `MusicInit`
  600 случаев, 0 расхождений): +0x2EC = +0x2EE = 0xFF, +0x2ED = 0, +0x2F0 = 0xFF, +0x2F1 = 0; +0x2EF =
  `0x80083AE0(task + 0x70) % 6` (ГСЧ: s = s * 17 + 17, результат s ^ (s, повёрнутое на 16)); режим 3 -> +0x2F1 = 2,
  режим 7 -> 1 (без интро); иначе при выдержке 0x800A9520 != 0: 0x801D5DDC != 0 -> интро 11 и +0x2F1 = 4, иначе 10
  (One Make) / 12. Если запрос есть, выдержка меньше длины интро поднимается до `секунды * 60` полей (0x800A951E и
  0x800A9520; интро 12 = 9 с = 540 полей - это и есть 540 полей гонки-заставки); затем при 0x800A951C (заставка)
  запрос = 0xFF (выдержка остаётся поднятой). Состояние ГСЧ задачи в продукте не восстановимо (зависит от истории
  меню) - `gt2game` засевает его часами; `--music N` задаёт трек гонки.
- `0x80029C60` зелёный свет (перенесено в `race_shell.cpp`): запрос = +0x2EF, флаг цикла 1. `0x80029C84` финиш: джингл
  13/16/14 по +0x2F1, флаг 0; вне режимов 0 и 3 +0x2F0 = 8. В заставке джинглов нет.

## 7. Реверб SPU

Загрузка EXE (`0x80010E14`, байты SCUS_944.88): `0x80079EF8(4)` - пресет 4: 0x40 байт таблицы `0x80092EA4 + 4 * 0x40` ->
регистры 0x1F801DC0..0x1F801DFE (dAPF1, dAPF2, vIIR, vCOMB1..4, vWALL, vAPF1, vAPF2, mLSAME, mRSAME, mLCOMB1, mRCOMB1,
mLCOMB2, mRCOMB2, dLSAME, dRSAME, mLDIFF, mRDIFF, mLCOMB3, mRCOMB3, mLCOMB4, mRCOMB4, dLDIFF, dRDIFF, mLAPF1, mRAPF1,
mLAPF2, mRAPF2, vLIN, vRIN), mBASE 0x1F801DA2 = `*(u16*)(0x80092E90 + 4 * 2)` = 0xF204 (рабочая область 0x79020..0x7FFFF);
`0x8007A0E0(1)` - бит 7 управления SPU (реверб включён); `0x8007A104(0x0FFF, 0x0FFF)` (непосредственные операнды вызова
0x80010EA8) - vLOUT/vROUT 0x1F801D84/86. Рантайм подтверждает (`spu_license.txt`): поле 11 - запись всех 32 регистров
и 0x1A2 = F204, поле 476 - 184/186 = 0FFF; EON 0x1F801D98/9A меняется по голосам (флаг голоса драйвера +0x24 = бит 0
флагов Play; у голосов двигателя 1). Значения пресета - стандартный "Studio Large" из psx-spx.

Порт: `Mixer` (`src\game\audio\mixer.*`): голоса с флагом 1 суммируются (после громкости голоса) во вход реверба;
реверб - публичный алгоритм psx-spx (отражения SAME/DIFF с IIR, 4 гребёнки, 2 всепропускающих звена, выход * vLOUT)
на 22050 Гц в своей 16-битной рабочей области с насыщением; пресет и mBASE читаются из EXE образа
(`audio::GameReverb`), глубина 0x0FFF - константа кода. Отклонение от железа: вход усредняется по двум кадрам, выход
интерполируется линейно (у железа 39-точечные полуполосные фильтры). Наш SPU рантайма (`src\machine\spu.*`) реверб
не реализует, поэтому объективного сравнения "тот же вход через оба" нет; строка стенда `Reverb` измеряет импульсный
отклик (импульс 16384: первый выход 43 мс, пик 485, -20 дБ за 1.45 с, -40 дБ за 3.98 с по интегралу Шрёдера).
`GT2_AUDIO_WAV=<dir>` пишет для прослушивания: `reverb_impulse.wav`, `engine_dry/wet.wav` (луп 20403.es), `impact_dry/wet.wav`
(сэмпл 5 se01.ins), `music_t1_ours.wav` / `music_t1_spu.wav`. `gt2game --no-reverb` выключает реверб для A/B;
`--record-audio <wav> <сек>` пишет выход устройства в WAV и выходит.

## 8. Звуки и музыка меню GT-режима (2026-09-19)

В меню GT-режима нет XA и `MUSIC.DAT`: эффекты - one-shot сэмплы резидентного банка `sound/sys.ins`, музыка -
секвенции SEQG `sound/spu_02..10.seq` на инструментах `sound/gtmseq.ins`. Адреса - US Sim v1.2, ovl4 = GT2.OVL член 4.
Код: `src/gt2formats/seqg.*` (SEQG + таблица программ INST), `src/game/audio/sequencer.*` (плеер),
`src/game/audio/menu_audio.*` (эффекты, выбор трека, банки), подключение - `tools/gt2game/menu_mode.cpp`
(`--no-sound` - без звука, `--no-reverb`, `--record-audio <wav> 0` пишет WAV и `<wav>.events.txt`: эффекты, старт трека,
ноты, параметры каждого голоса).

**Банки.** `sys.ins` (именованный id 0xF7) грузит EXE (`0x80010868` -> `0x80011CE4`): данные 0x8610 байт в SPU 0x1010,
11 сэмплов, резидентно. `gtmseq.ins` (id 0xEC) грузит вход в GT-режим (`0x80013CF8` -> `0x80018F6C` -> `0x80022874`): данные в
SPU 0x9630, 226 сэмплов, 44 программы. Именованные id файлов каталога `sound/` идут подряд в порядке тома (arcade.ins,
arcade.seq, arcseq.ins, затем 0xEC gtmseq.ins, 0xED se01.ins, 0xEE..0xF6 spu_02..spu_10.seq, 0xF7 sys.ins; таблица
id -> файл тома `0x801E2EF0`).

**Эффекты `0x80060840(id)`.** Пары {левый, правый} индексов сэмплов sys.ins в EXE `0x8009160C` (10 пар): одинаковые - один
сэмпл с pan 0x40, иначе левый с pan 0 и правый с pan 0x7F; каждый через `0x80078900` -> `0x800784A0` (`PlaySample`,
громкость 0x4000, приоритет сэмпла, громкость эффектов 0x801C9994 = 0xC0). Id: 0 зуммер (курсор упёрся, "назад" без
цели, действие невозможно), 1 выбор / подтверждение, 2 назад / закрытие списка, 3 конец мойки (стерео пара), 5 шаг курсора,
6 шаг в списке; 4 / 7 / 8 - титул, карта памяти, гонка. Голоса (адрес / 8, pitch, громкость L / R, ADSR, длительность,
реверб): id 5 = 0CA8 / 0C4B / 0F32 0F62 / 9FFF 5FC0 / 74 / да; id 0 = 0658 / 074F / 16A8 16F1 / 80FF 5FC0 / 53 / нет;
id 1 = 0ADA / 05CD / 1A20 1A73 / A6FF 5FC0 / 140 / да; id 2 = 0ADA / 03DF / 1DDB 1E3B / 80C0 5FC0 / 140 / да - равны
регистрам SPU захвата оригинала (`gt2play --spu-log`) и выходу нашего порта (`events.txt`, строки `effect-voice`).

**SEQG.** `+0` "SEQG", `+4` указатель на себя (0 на диске), `+8` u32 число секвенций (везде 1), с `+0xC` дескрипторы 0x48 байт:
u16 громкость (0x4000), u16 (не читается), u32 темп, 16 x u32 смещений дорожек от начала файла (`0x8007A1C4` прибавляет
адрес файла). Поток дорожки: VLV-дельта (как в MIDI, 7 бит на байт), затем события, после каждого (кроме `00`) - VLV-дельта:

| Байты | Событие (`0x80079744`) |
|---|---|
| `1nnnnnnn vel VLV` | нота n, скорость, длина |
| `01hhhhhh ll` | pitch bend: `((b0 << 8 \| b1) & 0x3FFF) + 0xE000` как s16 (центр 0) |
| `001ccccc` | начало цикла, счётчик c + 1; возврат - к дельте после этого байта |
| `00` | конец дорожки (без дельты) |
| `01 c` | начало цикла со счётчиком c (0xFF - бесконечно) |
| `02` | конец цикла: счётчик 0 -> снять уровень, иначе уменьшить (кроме 0xFF) и вернуться |
| `03 p` / `04 v` / `05 p` | программа / громкость дорожки = velT[v] / pan |
| `06 b1 b2 b3` | темп, 24 бита big-endian |

Все 16 дорожек всех 9 файлов: вступление, затем `01 FF` (бесконечный цикл).

**Плеер** (`0x8007A300` старт, `0x8007A4D8` стоп, тик `0x80079A38` раз в поле 60 Гц): аккумулятор += 480000000 / 60 за поле;
тиков = сколько раз из него вычитается темп, пока он > 0; у каждой дорожки countdown -= тики, пока < 1 - событие + дельта.
Нота (`0x80079460`): программа INST (таблица 1: u32 смещения записей `{u8 n, u8 pan, s16 vol, u8 idx[n]}`); для каждого
сэмпла программы с `+0xC <= нота <= +0xD` - слот из 25 (поиск по кругу от курсора, свободен - хэндл < 0; нет - нота
пропадает); `k = ((дорожка.eff * прог.vol >> 14) * velT[vel]) >> 14`, `v = k * сэмпл.vol >> 14`, громкость голоса
`PanVolume(v * v >> 14, clamp(дорожка.pan + прог.pan + сэмпл[+9] - 0x80, 0, 127))`, pitch `NotePitch(нота * 256 + (bend *
(bend < 0 ? сэмпл[+0xE] : сэмпл[+0xF]) >> 5), сэмпл.baseNote)`, ADSR / длительность / приоритет / флаги - сэмпла; слот
отпускается через `длина + тики + countdown` тиков. Обновление слотов (`0x80079B64`, тот же тик): без плеера - Release +
Detach; счётчик слота; bend дорожки изменился - SetPitch; eff / pan - SetVolume. velT - таблица EXE `0x800900B8` (128 x
u16). Громкость музыки: мастер = 0x801C9993 (0xF0) * 0x4000 / 255 = 0x3C3C; eff дорожки = мастер * громкость >> 14.

**Треки меню.** Байт 2 флагов страницы (0xFF - не менять) = трек t; `0x8001D2CC` при t != текущему -> `0x80018FA4(t)`: стоп
сразу (`0x80022934`), через 2 обновления вида (`0x80019028`) `0x800228D4(t)`: файл = ovl4 `0x80052A50[t]` (u32 id 0xEE..0xF6
= spu_02..spu_10, это НЕ таблица потоков), секвенция 0, всегда с начала. Уход в гонку / выход - стоп (`0x80018FF0`), трек
запоминается в `0x801EF5FC` и снова запрашивается при возврате (`0x8001D118`). Страницы: 0 (карта) - 7, 920 (Home) - 6,
921..927 / 929 (лицензии) - 8, города - 1..4, 810 - 0, 831 - 5 (по `gt2tool menu-dump`).

**Сверка (2026-09-19).** Захват оригинала `work\re\menu_sound\spuA.txt` (маршрут `1400:cross,...`, карта мира): все 155
key-on музыки карты за 358 полей (адрес, pitch, громкость L / R, ADSR, поле) совпадают с голосами нашего секвенсора
(`gt2game --menu --record-audio work\play\menu2\menu.wav 0 --menu-script "100:right,..."`, строки `voice`, сдвиг кадров
1752), 0 лишних и 0 недостающих; ноты секвенсора равны модели `work\re\menu_sound\seqsim.py`, которая воспроизводит все 1038
захваченных нот двух треков. Отличия: у нашего микшера 48 голосов против 24 у SPU (кража голосов не сверялась); id 4 / 7 / 8
не захвачены; громкости настроек (0xC0 / 0xF0) - константы из дампов, а не из опций карьеры.

## 10. Порядок кадра и car + 0x868: звук разделённого экрана 2P (US Arcade v1.1, 2026-09-19)

Адреса Sim v1.2 (на Arcade 0x800133F0 / 0x800146D8 / 0x80014ED0 те же). Улики: objdump оверлея гонки (`work\re\race_demo\ram.bin`,

- Кадр: тик физики 0x8003EBF0, камеры 0x800100F4, тик HUD 0x8002E550, затем проход звука (0x80015DF4 -> 0x80014ED0 / 0x80014E6C),
  и только потом отрисовка вида 0x800292A0 (вызов 0x80015EE0), в которой 0x800133F0 / 0x800140A4 пишут car + 0x868 / + 0x80C /
  + 0x804 / + 0x808. Значит, звук кадра k берёт вектор, расстояние и громкость по расстоянию из отрисовки кадра k - 1 (и её флаг
  разделения), а скорость / направление / оси камеры (+ 0xFC / + 0xE4 / + 0xEC / + 0xF4) - уже кадра k. Первый проход звука после
  старта гонки слышит нулевой вектор (отрисовки ещё не было): доплер 0x1000, громкость 0, pan 0.
- car + 0x868 (скорость машины для доплера) = новая позиция 0x8001336C МИНУС прошлая car + 0x830, а car + 0x830 получает смещение
  центра тяжести (матрица * (0, 0, car + 0x5A) >> 8) только после этого; у стоящей машины это смещение с минусом (на решётке
  tahiti_t_2p: (7999, 38, 22)) - отсюда доплер стоянки на старте.
- Нормализация 0x80081164 и скалярное произведение 0x80081500 - GTE (порт camera::VectorLength; MVMVA sf 1, IR1 с насыщением),
  а не float: иначе pan / доплер отличаются на 1..3.

Порт: `RaceAudio::StepTwoPlayer` / `PrimeTwoPlayer` (значения прошлой отрисовки по машинам `CarView`; `ViewCar` = 0x800140A4,
`CarVelocity` = car + 0x868 0x800133F0, `MixCar` = 0x800146D8), точные поля камеры в `Listener` (`cameraPosition`,
`cameraAxisSide`, `cameraAxisRight`). Одиночная гонка (`RaceAudio::Step`) берёт ту же скорость и ту же GTE-арифметику, но слушатель
race_view по-прежнему float и покадрово не сверяется. Сверка: `GT2_SOUND_COMPARE=1 gt2game <arcade.bin> --race --track tahiti_t_2p
--ai-player --frames-compare <захват>` - race.bin 6539 / 6539, hc3 6539 / 6539, p2win 7039 / 7039 кадров, объекты звука обеих машин
= оригинал (раньше кадры 1..308 стоянки на старте отличались).
