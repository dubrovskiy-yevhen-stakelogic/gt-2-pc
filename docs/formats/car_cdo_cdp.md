# Car model (.cdo/.cno) and texture (.cdp/.cnp)

Status 2026-09-18. Verified on US Simulation v1.2 (EXE SHA-1 3030aa27...), all 4,440 files in `carobj/`
parse with `gt2tool car-scan` (0 errors). Parser: `src/gt2formats/car_model.*`, `car_texture.*`.
Starting point: Nenkai's MIT 010 templates (research: SUBMANIAC, commongear, pez2k). Differences we
measured on real bytes are marked **[differs]**.

## CDO / CNO

| Offset | Field | Confidence |
|---|---|---|
| 0x00 | `"GT"`, u16 version = 2 | high |
| 0x08 | wheel dish RGB | template only |
| 0x18 | s16 wheel radius F, width F, radius R, width R (1/4096 m) | medium (captured wheel: 1311 / 798 vs 1294 / 839) |
| 0x20 | 4 x {s16 outerFace, y, x, z}: FL, FR, RL, RR, 1/4096 m. z = lateral CENTRE, x longitudinal (negative = front), y height; outerFace = z +- width / 2 | high: matches the wheel transforms the original feeds to the GTE (us36n: 1497 / 3033 / 2523 LOD0 units = 2965 / 6064 / 5045 here) |
| 0x40..0x867 | runtime area (wheel meshes generated by game code), zero in files | template only |
| after the last LOD | shadow block, see below | high |
| 0x868 | u32 LOD count (always 3 in corpus) | high |
| 0x86C | 3 x {u16 0, u16 max distance, u32 file offset of LOD block or 0} **[differs]** | high |
| 0x884 | LOD blocks, packed back to back | high |

LOD block: `u16 counts[10]`, `u32 offsets[10]` (relative to block), `s16 bbox[8]`, `s16 scale`, `s16 unknown`; 0x50 bytes.

- counts: [0] vertices [1] normals [2] tris [3] quads [6] uv tris [7] uv quads. [4] [5] [8] [9] are **always 0** in the corpus.
- offsets: [0] vertices [2] normals [3] tris [4] quads [7] uv tris [8] uv quads **[differs: template calls [2] the tris offset]**.
  Offsets of empty blocks may be 0 or stale.
- Vertex: 4 x s16 (x, y, z, 0). Normal: u32 packed 3 x signed 10 bit (unverified visually).
- Polygon 16 bytes / textured 28 bytes as in the template. **Quad corners are in ring order** (corpus vote 534,879 ring / 300 strip / 2,218 degenerate).
- Prim codes seen: 0x20, 0x28 (flat), 0x25, 0x2D (textured, raw-texture bit set), 0x2C (8 polys). No gouraud, no semi-transparent faces.
- Raw palette values seen: 0x00-0x03, 0x40-0x43, 0x80-0x83, 0xC0-0xC2 -> CLUT = (raw >> 4) + (raw & 0x3F). CLUT 15 is never referenced by files (brake-lit swap happens at runtime).

Axes: +Y up, -Z front, -X left (right-handed; matches glTF as is).

Scale (hypothesis, holds for all 2,196 real cars; outliers are menu objects `gt--*`, `gtl*`, `a26ss`):
metres = units * 2^(lod.scale - 16) / 4096. Check: `nr34n` body length 4.677 m / wheelbase 2.734 m
vs real R33 GT-R 4.675 / 2.720.

Observations relevant for VR: windows are opaque painted texture; there is no interior; wheel arches are open holes.

## Shadow block (after the last LOD, 196 bytes on the attract cars) **[new]**

`u16 vertexCount (24), u16 triCount (2), u16 quadCount (16), u16 0; 4 x { s16 v, s16 0 } = xmin, zmin, xmax, zmax;
u32 0x11 | n << 16 (n = 4868 us36n, 5117 ulcun ... unknown); vertexCount x { s16 x, s16 z } (LOD 0 units);
(tri + quad) x u32`: four 6-bit vertex indices (bits 0-23), bit 31 = fully shaded polygon; otherwise corners 0-1 are
the unshaded outer edge and 2-3 the shaded inner edge (ring order). The original draws it as gouraud quads with
GPU blend mode 2 (B - F, `E1 tpage bits 5-6 = 2`), corner colours 000000 / FFFFFF, on the ground plane with the
car's heading, 271 LOD 0 units (0.13 m) below the body origin of us36n. Verified: 18 primitives per car in the
captured draw list = 2 tris (FFFFFF) + 4 interior quads (FFFFFF) + 12 edge quads (00 00 FF FF).

## What the original draws per car (Seattle attract race, field 3600, `gt2play --prims`) **[new]**

- Textures in VRAM: car n at (320 + 64 n, 256) (the whole 256 x 224 .cdp image unchanged), its 16 CLUTs of the
  chosen paint at (320 + 64 n + 16 (c % 4), 480 + c / 4); the runtime CLUT word = base + rawPalette, so
  `rawPalette` is `(row << 6) | column` of that 4 x 4 layout. CLUT 15 is the brake-lit variant.
- Body polygons: POLY_FT4 / FT3 with the RAW bit (0x2D / 0x25, colour 000000) - no GTE lighting at all; the shading
  is the per-polygon CLUT choice baked in the file.
- Reflection pass: right after each body polygon the same screen quad is drawn again as POLY_FT4 semi-transparent
  (0x2E, colour 606060, tpage blend mode 1 = B + F) with UVs into a 128 x 128 4-bit environment map at VRAM (576, 0),
  CLUT (368, 511). The map is `crstim.arc` ("@(#)GT-ARC", u16 version 1, u16 count 6 at 0x0E, index of
  {u32 offset, u32 size, u32 size} at 0x10; entries 3 / 4 / 5 at 0xF98 / 0x2FD8 / 0x5018 are the three 128 x 128
  maps, authored at TIM position (384, 0) / CLUT (304, 511) and relocated by +192 / +64 words). Seattle uses entry
  3 (its 4096 image words and 16 CLUT words equal the captured VRAM; entries 4 / 5 differ in ~1500 words). The
  choice (race load 0x800274D4, 2026-09-19): entry 3; entry 5 when bit 0 of the course's `.crsinfo` flags (u16 at
  entry + 8) is set; entry 4 when bit 1 is set (bit 1 wins); the loader rewrites the TIM header to image (576, 0) /
  CLUT (368, 511) before the upload (it also uploads arc entry 0 to (608, 64) / CLUT (368, 509)). Bit 0: Special
  Stage Route 5, Rome-Night, Clubman Stage Route 5, Deep Forest (night / dusk courses); bit 1: Red Rock Valley,
  spL1..3. Seattle and TC_lisence (flags 0 / 0x40) -> entry 3, as both captures show.
- Reflection UVs (resolved 2026-09-19, car drawer 0x80061798 -> 0x800616C4): once per car and frame the game runs
  MVMVA over the LOD's normal table with the car's rotation in the camera frame scaled to 512 (= 4096 / 8, the
  normals have |n| = 512) and translation (64, 64): `u, v = 64 + ((R512 . n) >> 12)` with n = (bits 2-11,
  12-21, 22-31) of the packed normal word (i.e. CarNormal's z, y, x), R512 = trunc(R / 8) - the view-space normal
  mapped onto the map's disc, no aspect factor. Each corner of a polygon uses its own normal (normal[i] of the
  record: bits 5-13 of the u16 at +4, then bits 1-9 / 10-18 / 19-27 of the u32 at +8), the GPU quad is emitted as
  (v0, v1, v3, v2). Only polygons with bit 15 of the u16 at +6 (`renderFlags`) draw the pass (155 of 223 on
  us36n LOD 0). Verified on the captured field 3600: of 51 matched second-pass quads / triangles, 190 of 204 corner
  UVs equal the formula exactly and 14 are off by one (our R is reconstructed from the rounded 2048-scale draw
  matrix). Native: `SceneAssets::UpdateCarReflection` rebuilds the pass per frame from the camera axes.
- Wheels (mesh generated at runtime, GTE input captured): 16 segments; outer radius R, rim radius r, half width w
  (us36n LOD 0: 1311 / 742 / 399 in 1/4096 m; other cars r / R = 0.566..0.606); vertex list = 17 (outer, inner)
  pairs at +w, 17 (outer +w, outer -w) pairs, 16 outer at -w, then the rim square (+-r cos(pi/16), at +w - dish
  depth 245) with its centre. Drawn as: black (000000) sidewall annulus and tread, grey (808080) inboard disc, rim =
  four POLY_FT4 from the square's centre with uv (0..47, 0..47) of the car texture and CLUT 0 (which is a grey ramp
  in every paint), colour 808080 (neutral). The LOD 1 wheel has 8 segments.
  **Generator found (2026-09-19, `gt2export/car_mesh.h`, gt2verify row WheelArea = 0 mismatches):** the race's car
  setup 0x80017FA0 takes per axle R = body + 0x3E4 (the physics wheel radius, not the .cdo 0x18 value), W = body +
  0x3EC (us36n 798), r = R * (4096 - (body + 0x3F0 << 12) / R) >> 12 (R minus the tyre height: us36n 1286 / 728) and
  the dish depth 0x80091A70[(CarConfig + 0x00 >> 8) & 3] = 0 / 81 / 163 / 245 (the wheel word of the race slot);
  0x80061308 writes model + 0x40: + 4 / + 6 the rim's z = W / 2 - dish (the rim sits INSIDE the tyre, not on its outer
  face), + 8 / + 28 the rim square with half size r (exactly r: the inner ring of the sidewall is a 16-gon whose
  apothem is r, i.e. its edges touch the square), then the executable's templates 0x80091670 / 0x80091878 /
  0x80091990 (16 / 8 / 6 sides) scaled by 0x800611F8. The outer ring's apothem is R (vertices at +-11.25 + 22.5 k
  degrees). Rim quads (0x800670F0): (r, r) uv (47, 0), (-r, r) (0, 0), centre (23, 23), (-r, -r) (0, 47) and (r, r),
  (r, -r) (47, 47), centre, (-r, -r). The menu car uses 0x80061504's defaults (.cdo 0x18 radius / width, r / R =
  3072 / 4096, dish 122). The strips' colours are picked per quad by 0x80066EF8 (ported 2026-09-19, below).
  **Strip colour rule 0x80066EF8 (ported, gt2verify row WheelStrip = 0 mismatches):** each group of the stream (u32 count,
  count pair records) becomes count - 1 flat POLY_F4 (code 0x28, 5 words) of consecutive pairs, GPU (A_k, B_k, A_k+1, B_k+1)
  with A = (T0, T1, T2), B = (T4, T5, T3). The packet of quad k is written while pair k + 2 is transformed (the loop reads the
  next group's count word as its last, never drawn, vertex pair); it is linked only when no vertex of the quad raised FLAG
  bit 31. Colour: n1 = NCLIP(A_k, B_k, A_k+1), n2 = NCLIP(B_k, A_k+1, B_k+1); grey = the LOD's colour word (.cdo + 0x08 + lod
  * 4 = scratch + 0x3B0, stored at 0x80067750 before each wheel with the car LOD; us36n 0x888888) when n1 >= 0 and n2 < 0, else black; the mirror byte scratch +
  0x398 (negative) inverts the test (n1 < 0 and n2 >= 0) - 0x800672A4 flips it for the wheels whose matrix is mirrored, so
  the rule is the same physical face on every wheel: grey = the faces seen from inside the wheel (the inboard disc through
  the rim's transparent texels, the tread's inside), black = seen from outside. Ordering-table depth: the largest of the
  quad's four SZ when grey, the smallest when black, (z << scratch + 0x98) >> 13, at most 4095, entry + 1 of scratch +
  0x64. Check: `gt2verify` WheelStrip runs 0x80066EF8 on every car's streams (both axles, LODs 0..2) after 0x8007B778 loads a
  random GTE view, random shift / mirror byte / colour word; the whole RAM and scratchpad after it equal ours
  (`car_mesh.h EmitWheelStrips` / `WheelQuadGrey`): race_demo 432 cases (8285 quads, 3961 grey), license_race 72 cases (1342
  quads, 623 grey), 0 mismatches. Native mesh (`BuildWheelMesh`): every strip quad as two one-sided copies (kCullBack): the
  face turned towards the wheel centre in the .cdo's grey, the other black; glTF exports keep one double-sided copy
  (`CarMeshOptions::wheelStripFaces = false`: sidewall and tread black, disc grey).
  **Wheel transform per frame (2026-09-19, disassembly of 0x800140A4 / 0x800670F0, US Sim v1.2):** 0x800140A4 fills per wheel
  w (0 FL, 1 FR, 2 RL, 3 RR) a stack record for 0x80067444: {x, y, z} = car + 0x7C4 + w * 0x10 (0x800133F0: -/+ half track,
  ride reference - travel, the .cdo wheel x), yaw = wheel + 0x0C (car + 0x498 + w * 0x68, steer angle) - 1024 on even wheels
  / + 1024 on odd ones, pitch = -(car + 0x394 + axle * 2) (body + 0x368: camber) on even wheels / + on odd ones, roll = wheel +
  0x20 (car + 0x4AC + w * 0x68: the rolling angle of the drivetrain). 0x800670F0: odd wheels yaw += 2048; wheel matrix =
  camera x car x T(x, y, z << 4) x 0x80081374(yaw, pitch, roll) (m = Ry(yaw) Rx(-pitch) Rz(roll)), then column 2 negated on odd
  wheels (mirror). The rim geometry and texture are static (no texture swap by speed): the wheel turns through Rz(roll).
  The car + 0x7C4 record's +8 / +0xA / +0xC halfwords are not these angles (never written during a race, watched 2800..3700).
  Native (`car_mesh.h WheelModelMatrix`, `CarMeshOptions::wheelsAtOrigin`, `SceneAssets::AppendCarItems(..., wheelModels)`):
  each wheel is built at the origin in its steer-0 orientation (Ry(-1024), mirrored on the right) and drawn with T(centre)
  Ry(yaw) Rx(-pitch) Rz(roll) Ry(1024); the race view interpolates steer / travel / rolling angle between steps. Menus
  and other callers without transforms draw the wheels at their rest centres (unchanged).
- Paint: the paint of a car is the one whose 16 CLUTs equal the VRAM CLUTs (`SceneAssets::FindPaint`); the attract
  race uses paint ids 109 (us36n), 103 (ulcun), 98 / 99 (ulrrn), 112 (cc69n), 98 (ulsbn).

## CDP / CNP (always 45,984 bytes)

- u16 paint count (1..16 in corpus), then **u8** paint id per paint **[differs: not u16]**.
- 0x20: per paint 0x240 bytes = 16 CLUTs x 16 colours (PS1 15-bit, R in low bits) + illumination mask + paint mask.
- 0x43A0: 256x224 4bpp indices, low nibble = left pixel. Colour 0x0000 = transparent.
